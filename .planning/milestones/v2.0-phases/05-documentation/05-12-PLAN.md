## 도우미 하나로 모으는 까닭 (G3-Q1 이 planner 에게 맡긴 선택)

- 같은 모양(reader 가 analyzer 와 다르게 줄을 나눔)이 세 번째로 나왔다. 줄을 나누는 규칙을 이름 붙은 한 곳에 두면 "YAML 을 줄로 나눌 때는 이것을 쓴다" 가 코드로 보이고, 자동 검증이 "여섯 자리와 `pubspecReleaseVersion` 이 모두 그 이름을 쓴다" 를 셀 수 있다 (주석이 아닌 줄의 `splitYamlLines(` 8개 — 정의 하나 · 쓰는 곳 일곱). 도우미의 꼴은 한 줄 화살표 함수 `List<String> splitYamlLines(String text) => const LineSplitter().convert(text);` 로 정한다 (79자 — `dart format` 이 나누지 않는다).
- `const LineSplitter().convert` 는 `\r\n` · `\r` · `\n` 을 한 번씩 줄바꿈으로 본다 — package:yaml 3.1.4 의 `_isBreakAt` (CR · LF) 과 같고, 같은 파일의 `readAsLinesSync()` (`significantLines` · `readMarkerBlock` · README 읽기)와 같은 규칙이다. `replaceAll('\r', '\n')` 은 CRLF 를 두 줄로 세어 줄 번호가 밀리고, 정규식에 `\r` 을 더하는 것은 소유자가 고르지 않은 "철자를 하나 더 받는" 수정이다.
- `stripPlugins` 는 나눈 줄을 `'\n'` 으로 다시 잇는다 — 복사본은 LF 만 담게 되고 줄 수 · 줄 번호는 YAML 이 세는 원본과 같다 (원본의 마지막 줄바꿈은 복사본에서 빠질 수 있다 — analyzer 의 진단과 줄 번호에는 영향이 없다, 계획 단계의 복제본에서 기준 실행 · M33 · M37 로 확인). `copyLines` 는 그 복사본을 같은 도우미로 나누므로 `readRuleNameAt` 이 analyzer 가 말한 줄을 읽는다 — 고치기 전에는 M80 의 `[2/10]` 줄 끝 이름이 `(no_dynamic_casts)` (원본의 다음 줄)였다.
- `pubspecReleaseVersion` 은 지금 `pubspec.yaml` 을 여러 줄 정규식으로 읽는다 — Dart 정규식의 줄 경계는 CR · LF 에 U+2028 · U+2029 를 더하고 YAML 1.2 · pub 은 CR · LF 뿐이라, 주석 줄 안에 U+2028 로 숨긴 `version:` 을 읽는다 (planner 의 함수 단위 확인 `9.9.9`, orchestrator 의 정규식 단위 재현). 소유자 결정 G3-R2-Q1 (IN 7) 로 같은 도우미로 나눈 줄을 한 줄씩 본다 — 정규식은 그대로 한 줄에 쓰고 `multiLine` 만 뺀다 (한 줄 안에서 `.` 는 U+2028 을 넘지 못하므로 숨긴 값이 든 주석 줄은 `^version:` 에 맞지 않는다). 다시 이은 글에 여러 줄 정규식을 쓰거나 U+2028 을 줄바꿈으로 바꾸는 구현은 숨긴 값을 그대로 읽는다 — 함수 직접 호출 `pubspec=2.0.0` 이 그 구현을 가른다 (계획 단계 복제본에서 확인). 이 함수는 줄을 다시 잇지 않으므로 줄 수 문제가 없다.
