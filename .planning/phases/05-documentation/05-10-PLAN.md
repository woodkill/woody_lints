## 닫힌 목록의 줄 규칙 (`findUnexpectedKeys`)

- 키 줄은 열 0 에서 `^([A-Za-z_][A-Za-z0-9_-]*):(?:[ \t]|$)` 에 맞는 줄이고, 키 이름이 받는 목록 안이어야 한다. 이 꼴이 아닌 열 0 의 비주석 줄 — 콜론 앞 공백, 따옴표 키, `? ` 키, 앵커 · 병합 키, `- ` 항목, `---`, flow 맵 — 은 모두 받지 않는 줄이다 (G2-Q1 의 "명단에 없으면 모두 막는다").
- 아래 키 목록이 있는 키(`lib/codegen.yaml` 의 `analyzer`)는 그 줄에 값이 붙으면(`# 주석` 만은 된다) 아래 키를 읽을 수 없으므로 받지 않는 줄이다. 아래 키 목록이 없는 키의 값(`include: …`, `plugins: {…}`)은 이 검사가 보지 않는다 — 값을 읽는 검사(`declaredRuleNames` · `enabledLanguageOptions` · `readShippedPluginConstraint`)의 몫이고, 그 70 들이 그대로 남는다.
- 첫 비주석 줄이 들여 쓴 줄이면(최상위 키가 열 0 에서 시작하지 않는 파일 — YAML 로는 같은 최상위 맵이다) 그 줄 하나를 받지 않는 줄로 담고, 같은 들여쓴 최상위의 나머지 줄은 그 아래로 보아 다시 담지 않는다 (M73).
- 아래 키는 그 키 다음 첫 비주석 줄의 들여쓰기를 "바로 아래" 로 기억해, 같은 들여쓰기의 줄은 키 이름이 목록 안이어야 하고 그보다 얕은 줄도 받지 않는 줄이다. 더 깊은 줄(`errors:` 의 진단 이름, `exclude:` 의 glob)은 보지 않는다.
- 여러 줄에 걸친 flow 표기는 받지 않는다 — 블록 꼴로 적는다 (지금 조각 셋 모두 블록 꼴).

## 표시 구역이 든 절의 경계 (`findListLinesOutsideMarkers`, G2-Q3 이 planner 에게 맡긴 규칙)

- 절은 마커로 찾는다 — start 마커 앞에서 가장 가까운 제목 줄의 다음 줄부터, end 마커 뒤의 첫 제목 줄 앞까지 (없으면 파일 처음 · 끝). 제목 이름(「받는 규칙」)에 기대지 않아 제목을 바꿔도 같은 절을 본다. 지금 README 로는 89행 `## 받는 규칙` 다음 줄부터 190행 `### 조각마다의 설정` 앞까지다.
- 제목 줄은 펜스 코드 블록 밖에서 `^ {0,3}#{1,6}(?:[ \t]|$)` 에 맞는 줄 — 수준을 가리지 않는다 (`###` 에서도 끝난다, M76). 펜스 안의 `# …` 줄(YAML 주석)은 제목이 아니다 (M77). setext 제목(`===` · `---` 밑줄)은 제목으로 보지 않는다 — 그러면 절이 더 길어져 더 많은 줄을 보게 될 뿐 헛통과 쪽으로 가지 않는다.
- 목록 줄은 펜스 밖에서 `^[ \t]*(?:>[ \t]*)*(?:[-*+]|\d{1,9}[.)])(?:[ \t]|$)` 에 맞는 줄 — 구역 안 reader 가 읽거나 거부하는 꼴(`-` · `*` · `+` · `1.`)에 CommonMark 의 `1)` 과 인용 안의 목록을 더했다. `**굵은 글씨**` · `---` 구분선은 기호 뒤가 공백이 아니라 걸리지 않는다. 마커 둘 사이의 줄은 이 검사가 보지 않는다 (구역 안은 (d) 의 `readBulletBlock` 이 본다). 마커가 하나라도 없으면 이 검사는 빠진다 — (d) 가 `구역이 없다` 로 이미 실패한다.
- 펜스 판정은 `fencedLines` 와 같은 규칙(여는 줄의 문자 · 길이를 기억, 같은 문자만으로 된 같거나 긴 줄에서 닫힘)이고 줄 번호가 필요해 새 함수 `markFencedLines` 로 둔다 — `fencedLines` 는 G2-Q2 로 이번에 손대지 않는다.
</design>
